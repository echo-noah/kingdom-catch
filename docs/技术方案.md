# kingdom-catch -《洛克王国世界》屏幕识别统计 - 技术方案

> 版本：v1.0 | 状态：已确认

## 1. 项目目标与范围

### 1.1 目标
- **场景**：Windows PC 客户端《洛克王国世界》，**独占全屏**运行
- **短期目标**：实时识别并统计「丢球次数」「捕捉成功次数」，计算成功率
- **中期目标**：识别结果稳定后可扩展（捕捉失败原因、宠物品质等）

### 1.2 明确不做
- 内存读取、注入、自动操作（有封号风险，不采用）
- 训练重型深度学习模型（短期不必要）

## 2. 技术选型

| 项 | 选择 | 理由 |
|----|------|------|
| 语言 | Python 3.11+ | 视觉生态成熟 |
| 屏幕捕获 | mss（GDI 快照） | 独占全屏直接抓显示器，非 Hook，无封号风险 |
| 图像处理 | OpenCV + numpy | 模板匹配、HSV、帧差 |
| OCR | RapidOCR（onnxruntime） | 轻量免训练，CPU 推理够快；仅低频兜底 |
| 识别主方案 | 模板匹配 + 帧差触发 + HSV 颜色辅助 | 免训练，快速出活 |
| 配置 | YAML | 所有阈值可调 |
| 输出 | 控制台 + CSV + 会话 JSON | 实时统计 + 落盘分析 |

## 3. 总体架构

```
┌──────────┐  ┌─────────┐  ┌─────────────────────┐  ┌──────────┐  ┌─────────┐
│ 屏幕捕获   │→│ 预处理   │→│ 三层识别              │→│ 状态机     │→│ 统计输出  │
│ mss      │  │ 降采样   │  │ 帧差触发→模板匹配     │  │ 空闲→丢球  │  │ 控制台   │
│ DPI校准  │  │ 灰度/ROI │  │ →HSV/OCR 判定结果    │  │ →结果→空闲 │  │ CSV/JSON│
└──────────┘  └─────────┘  └─────────────────────┘  └──────────┘  └─────────┘
```

## 4. 识别策略（三层 + 兜底，容错设计）

> 游戏画面未知，设计原则：**缺模板也能跑**、阈值全可调、输出调试帧。

1. **帧差分**：灰度降采样后算绝对差，检测「变化激增」作为事件触发信号（可选开关，默认关闭，防误报）
2. **模板匹配（主方案）**：每帧在 ROI 上跑轻量 `matchTemplate`（1280 宽下约 10~20ms），识别「丢球动画帧」「捕捉成功/失败提示」，相似度超阈值才触发
3. **HSV 颜色辅助**：捕捉成功/失败特效若有专属光效色，用颜色像素占比做二次确认（需实测填参，无效可关闭）
4. **OCR 兜底**：仅在疑似结果界面出现时调用一次，读「捕捉成功/失败」文字做最终判定

## 5. 统计口径

| 指标 | 定义 |
|------|------|
| 丢球次数 | 状态机从空闲进入「丢球中」的次数（去重：同一动画持续帧只计一次） |
| 成功次数 | 结果判定为「成功」的次数 |
| 失败次数 | 结果判定为「失败」的次数 |
| 未知次数 | 丢球后超时无结果 |
| 成功率 | 成功 / (成功 + 失败) |

## 6. 里程碑

| 阶段 | 内容 | 验收 |
|------|------|------|
| M1 | 捕获链路 + 调试工具 | 能抓帧、能保存调试帧，帧率达标 |
| M2 | 模板工具 + 三层识别实现 | 用户截模板后，单帧识别正确 |
| M3 | 状态机 + 计数去重 | 模拟序列计数正确 |
| M4 | 统计输出 + 主循环 | 实机跑一场战斗，统计合理 |
| M5 | 实机调优 | 准确率 ≥ 95%（用户实测确认） |

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| 游戏画面未知，模板设计难一步到位 | 容错设计 + 模板工具 + 调试标注帧；模板随时补截，热加载重载 |
| 独占全屏抓帧开销 | 降采样到 1280、fps=10；快照式捕获无 Hook，不影响游戏 |
| 动画导致模板误报/漏报 | 阈值可调 + HSV/OCR 二次确认 + 状态机防抖 |
| OCR 性能 | 懒加载 + 仅事件帧调用 |
| 显示器分辨率/DPI 变化 | DPI 校准 + ROI 按比例缩放 + 降采样统一处理 |
| 实机效果未知 | M5 用调试工具实测调参，准确率目标 ≥ 95% |
